# 单词数据格式

单词数据放在 `js/data/words_*.js`，汉字表放在 `js/data/kanji*.js`，都需要在 `index.html` 里引入（放在 `conjugate.js` 之前）。
写完后运行 `python3 tools/validate_words.py` 校验（加 `--need-rd` 时，非外来语的词缺少 `rd` 会报错）。

## 单词文件

```js
// 注释：说明这个文件收了哪些主题
JP.addWords([
  { ...单词1 },
  { ...单词2 }
], "N5");
```

括号里是**严格 JSON**（双引号、不能有尾逗号、不能写注释），最后的 `"N5"` 是 JLPT 级别。

### 单词字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `W5-<主题>-<两位序号>`，如 `W5-food-04`。全局唯一，**定了以后不要改**（收藏、笔记、卡片进度都按 id 保存） |
| `w` | 是 | 书写形式，汉字用注音 `{漢字|かな}`；把 `{A|B}` 换成 B 后必须完全等于 `kana` |
| `kana` | 是 | 读音（平假名；外来语用片假名） |
| `pos` | 是 | 词性键，见 `js/words.js` 的 `POS` |
| `topic` | 是 | 主题键，见 `js/words.js` 的 `TOPICS` |
| `zh` | 是 | 中文释义，多个义项用「；」分隔 |
| `note` | 否 | 用法提示（易错点、搭配、变形特例、敬语等），一两句话 |
| `ex` | 是 | **恰好 2 个**例句：`[["日语", "中文"], ...]` |
| `rd` | 是（外来语除外） | 读音记法，1~2 条：`{"type": "类型", "text": "内容", "best": true}`，**恰好一条** `best`。外来语不写（`loan` 的原词就是读音记法） |
| `mn` | 是 | 联想记忆，1~3 条：`{"type": "类型", "text": "内容", "best": true}`，**恰好一条** `best` |
| `parts` | 否 | 词源拆解，只有真正能拆的词才写 |
| `loan` | 否 | 外来语出处：`{"lang": "英语", "src": "television", "note": "补充说明"}` |

### 例句 `ex`

- 只用 N5 程度的语法和词汇，句子自然、简短，是日本人真的会说的话。
- **所有汉字都要加注音** `{漢字|かな}`（校验脚本会检查）。
- 用 `<b>…</b>` 把目标词标出来，**每句恰好标一处**；动词、形容词变形后也标变形后的整体，如 `<b>{食|た}べ</b>ました`、`<b>{大|おお}きい</b>{町|まち}`。
- 两句尽量展示不同的用法或搭配。

### 读音记法 `rd`

中国学习者看汉字大多能猜到意思，真正难记的是**读音**。`rd` 专门帮助记住「这个意思 → 这个读音」，在详情页显示为「读音怎么记」，排在释义下面、例句前面。

- `type` 用以下之一，按这个优先顺序挑最自然的：
  - `语源`：读音本身有来历，如 果物 くだもの＝木（く）＋だ（の）＋もの。规则同 `parts`：**不要编造**；只是常见说法的写「常见说法」，说法不一的写「说法不一」。
  - `拆词`：拆成更简单或学过的日语词，如 友達＝とも＋だち、お手洗い＝お＋て＋あらい。
  - `音读规律`：音读词借助中文（普通话）发音的对应规律，如 先 xiān→せん（-n→ん）、生 shēng→せい（-ng→い/う）、入声字（如 学 xué→がく）多以く/き/つ/ち结尾。
  - `谐音`：用中文发音相近的字提示读音，如 行く：い≈“移”、く≈“去” → 移步过去。必须和假名发音足够接近；长音、促音、浊音不同时要在文字里提醒，**不能带偏发音**；不要低俗（例如不要用「行く」≈“一库”）。
  - `联想`：编的小场景、小故事，或借助学习者熟悉的名字（如 YAMAHA＝山葉 やまは），把读音和意思串起来。属于编的就标 `联想`，不要冒充语源。
- **每个非外来语的词都要写**，找不到语源和规律的训读词就用 `谐音` 或 `联想`。
- `text` 里要写出读音（假名），并且把读音和意思联系起来；不能只写「读音记 からだ」这种不起作用的话。
- 有两种不同思路时写 2 条，最自然、最好记的标 `best` 排第一；只有一种好思路就写 1 条。
- 特殊读法（熟字训，如 今日、眼鏡、部屋）要提醒「不按字读」。
- 文本里出现日语汉字可以加注音，可以用 `<b>` 加粗。
- 用 `python3 tools/add_rd.py rd.json` 可以批量写入（格式 `{"id": [rd 条目, ...]}`），它会把 `rd` 放在该词 `mn` 的前面。

### 联想记忆 `mn`

- `type` 用以下之一：`汉字`（借助汉字字义）、`画面`（场景、动作联想）、`谐音`（中文谐音，不要低俗、不要太牵强）、`词源`（来自语源的记法）、`外来语`（原词）、`对比`（反义词、近义词、成套词对比）。
- `best: true` 给最自然、最好记的那一条，排在第一条。
- 文本里出现日语汉字也可以加注音。

### 词源拆解 `parts`

只给**确实能拆**的词写：复合词、派生词、带前缀后缀的词、由汉字词素组成且字义能讲通的音读词。像「犬」「山」「行く」这种不能再拆的词不要写，页面会自动显示「汉字解析」。

```json
"parts": {
  "rows": [["とも", "友", "朋友、同伴", "「友」的训读"], ["だち", "達", "……们（复数）", "接尾词「たち」，接在后面变成浊音（连浊）"]],
  "sum": "「朋友们」→「朋友」",
  "origin": "补充说明语源（可选）",
  "cert": "确定"
}
```

- `rows` 每行 `[假名, 汉字, 意思, 说明]`。各行的假名拼起来必须等于 `kana`。没有对应汉字的部分，汉字写 `""`。
- `sum`：合起来的意思，可选。
- `origin`：补充说明，可选。
- `cert`（可信度）：
  - `确定`：构词清楚、没有争议，例如 自転車＝自＋転＋車、お手洗い；
  - `通说`：词典常见的说法，但不是百分之百确定，例如 果物＝木＋だ（の）＋物、時計 来自「土圭」；
  - `有争议`：有几种说法、没有定论。写明「说法不一」，**不要编造、不要只挑一种说成定论**。
- 拿不准的语源宁可不写 `parts`，也不要写错。

## 汉字文件

```js
JP.addKanji({
  "友": {"on": "ユウ", "kun": "とも", "zh": "朋友"}
});
```

- `on`：音读，片假名，多个用「・」分隔；
- `kun`：训读，平假名，送假名前加「-」（如 `た-べる`），没有训读写 `""`；
- `zh`：字义。
- 单词 `w` 里出现的每个汉字都必须在汉字表里（例句里的汉字不需要）。
